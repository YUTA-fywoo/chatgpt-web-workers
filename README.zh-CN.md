# ChatGPT Web Workers

**Astra 把握总目标，每个 Chat 完成一个可验收阶段。**

[English](README.md) · [下载 v1.1.0](https://github.com/YUTA-fywoo/chatgpt-web-workers/releases/tag/v1.1.0) · [更新记录](CHANGELOG.md) · [MIT 许可证](LICENSE)

面向 Codex 桌面版的协作 skill：由 Astra 统筹 **1–6 个普通 ChatGPT 极高 Chat**，较大且可拆分的任务主动使用 **4–6 个**。本项目把这些工作会话称为 Sol；Astra 负责总目标、阶段验收、跨部分判断和最终交付。

**安装后无需额外配置 MCP 服务器或 API Key。** 直接使用 Codex 桌面端已有的内置浏览器与会话读取工具；需要已登录 ChatGPT，且客户端与账号提供所需功能。

**通过内部读取回复，减少主模型的 token 开销。** 直接取得会话内容，避免为读取回复而反复把网页截图、界面结构和重复历史送入上下文；结合简要状态探测、原文缓存和后续重复过滤，把上下文留给成果与证据。首份完整成果仍完整接收，网页发送、必要健康检查和文件传输照常保留。具体节省量取决于任务，未宣称固定比例。

## v1.1.0 改进了什么

| 改进 | 实际规则 |
|---|---|
| 主动分担提示词负担 | 派发前规划独立范围；较大任务优先4–6个，总数仍为1–6个，替换会话也计入。 |
| 一次提示词，一个主要阶段成果 | 在可验收成果处结束，避免把发现、全面核查、排名和最终报告塞进同一轮；紧密相关的操作与必要自查可以一起做。 |
| 各个 Chat 独立续轮 | 按时收到完整回复后，验收并安排该负责人的下一阶段，其他 Chat 继续；每个 Chat 同时最多一个未回复任务。 |
| 保留原有工作规模 | 分阶段不把几十上百个的发现任务缩成少量试搜，不新增任意搜索上限；后续阶段围绕真实缺口调整。 |
| 内部读取、网页发送 | 内置工具读回复；首发、追问、修正、重试和其他 Chat 控制全部通过内置浏览器，不用内部发送兜底。 |
| 明确计时与恢复 | 每轮第10分钟首读、随后每5分钟；第15分钟首查网页、随后每10分钟；每个派发版本上限90分钟。 |
| 明确负责人和权限 | 新增外部证据由 Chat 用自身真实工具与权限收集；主端有账号、插件、API或本地路径不代表 Chat 有。 |
| 保存长期目标和状态 | 记录目标、版本、依赖、验收成果、缺口和下一动作；收到回复、验收通过、整个任务完成分别判断。 |
| 完整成果与重复过滤 | 保存原始回复，探测只回简要状态；新完整结果首次完整接收，后续按需读缓存或真正变化的内容。 |
| 按需加载说明 | 通用协作规则留在 workers；传输、文件、维护依据和历史测试分开加载，领域标准留给依赖 skill。 |


## 如何协作

1. Astra 明确总目标、最终成果和不可丢失的要求，分配独立范围与数量。
2. 顺序创建普通 Chat、确认极高并通过网页派发，Chat 并行生成。
3. 按时内部读取，核对会话、派发版本和完整性，保存证据。
4. 对完成的负责人独立验收与续轮，其他负责人继续；下一阶段对应真实缺口。
5. Astra 基于已有证据去重、分级、计算、裁决、整合，完成必要本地检查后交付。

新增搜索、打开原页核对或补证仍归 Chat。来源受阻、回复慢和交付压力不允许主端悄悄接管；用户明确授权主端采集时才改变边界。

## 等待与网页恢复

- 内部回复检查：第 **10、15、20……85分钟**，第 **90分钟** 最终检查。
- 网页检查：第 **15、25、35……85分钟**；两者同时到期先内部读取，完整结果已收到则跳过网页检查。
- 有报错按网页指示重试；没有结果且没有思考、处理或生成迹象才刷新一次，不能只因慢或缺少“正在思考”几个字而刷新。
- 刷新、重试、部分输出和上下文恢复均不重置期限；上一轮完整结束后的新任务才建立新时钟。
- 第90分钟内部结果不明确时检查已知网页；仍无法确认完整回复，就**保存进度并中断整个任务**。不得自动续跑、替换会话或主端代做，仅在用户明确要求后恢复。

90分钟取代开发期间曾采用的一小时设置，按每个派发版本计算，不是整个多阶段任务的总时长。已完整返回“无法完成”的说明按受限成果处理。详细定义见[通信说明](skills/chatgpt-web-workers/references/transport.md)。

## 安装与升级

```text
$skill-installer 从 https://github.com/YUTA-fywoo/chatgpt-web-workers
安装 skills/chatgpt-web-workers 这个 skill。
```

也可在[版本页](https://github.com/YUTA-fywoo/chatgpt-web-workers/releases/tag/v1.1.0)下载 `chatgpt-web-workers-v1.1.0.zip`，解压安装其中的 `chatgpt-web-workers`。若下载 **Source code (zip)**，取仓库内部的 `skills/chatgpt-web-workers`。

已测试的 Windows 桌面环境使用 `$CODEX_HOME/skills/chatgpt-web-workers`，通常为 `~/.codex/skills/chatgpt-web-workers`；以客户端实际识别目录为准。升级时保留个人改动并有意识地替换旧副本，避免同名重复安装。仓库另提供 `.codex-plugin/plugin.json` 插件封装。

**从 v1.0.0 升级：**六个技能文件一起更新，清理仍允许内部发消息、使用一小时超时、把大任务限为三个 Chat 或要求全员齐步续轮的本地覆盖规则。文件上传下载仍走网页。

## 使用示例

```text
使用 $chatgpt-web-workers 研究[主题]。有足够独立范围时使用4–6个Chat。
每轮只要求一个可验收阶段，保留完整采集目标，已完成的负责人独立续轮。
最终给出有证据、缺口说明和综合判断的报告。
```

```text
使用 $chatgpt-web-workers 分析这些文件。只向对应负责人提供必要输入，
保留最终目标，根据阶段结果安排后续任务，交付经过检查的最终文件。
```

```text
使用 $chatgpt-web-workers 为这些组件提出代码方案并作针对性评审。
保持职责独立，审阅方案、执行必要本地检查，然后整合验收通过的结果。
```

适用于研究、提取、写作、分析、计算、代码方案和评审，不强制研究流水线，也不机械规定每轮只能几步。小任务、强耦合工作或实际资源限制可以用1–3个。

## 提示词、证据与质量

任务包包含任务及派发版本、总目标的一句话关联、当前阶段目标、相关材料与约束，以及成果格式、验收条件、缺口和返回边界。后续发送相关变化，避免重复整段历史和未变全表；精简后仍须足以完成当前阶段。

设计参考 [OpenAI 的 Astra skill 指南](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)，采用简洁描述、按需加载和明确完成边界；Chat 提示词参考[推理模型提示建议](https://developers.openai.com/api/docs/guides/reasoning-best-practices)，保留直接目标、清晰材料分界和具体成果要求。Sol 专项来源见[设计说明](skills/chatgpt-web-workers/references/model-guidance.md)。4–6个偏好和计时是本项目规则，不是 OpenAI 官方并发建议。

确认普通 Chat 的可见“极高”，不把订阅 Pro 标识当 Pro 推理，也不把 API 参数写进提示词就当启用了能力。账号只有其他强度时，可明确要求调整本地版本，不能静默替换或谎称已验证。

**当前规则要求新完整成果首次完整交给主模型，并非每轮只看摘要。** 后续省略旧回复，复核时定向读缓存；整体判断仍可读完整合并结果。原文件上传、新生成文件下载均通过网页，检查真实字节与内容，详见[文件说明](skills/chatgpt-web-workers/references/files.md)。

目标是减少重复工作和无用上下文，同时保留证据。**尚无可发布的实测节省比例，也不承诺所有任务质量不变。** [验证记录](skills/chatgpt-web-workers/references/validation.md)保留原测试日期，本次发布不代表重新实测了全部网页能力。
